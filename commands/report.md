argument-hint: "<description>" [--type bug|feature] [--command <name>] [--severity critical|high|medium|low] [--include-logs]
---

## User Input
```text
$ARGUMENTS
```

You **MUST** consider the user input before proceeding (if not empty).

## Overview

Report bugs or request features for the ProveKit plugin directly from any project. Issues are created in `caburgoin/provekit` regardless of which project you're currently working in.

### Usage
```bash
/provekit.report "Pipeline staleness detector missed a layer"
/provekit.report "Add support for custom phase definitions" --type feature
/provekit.report "Capability test crashes on empty evidence" --command capability --severity high
/provekit.report "Phase advance lost history" --include-logs
```

### Cross-Repo Reporting
```
You're in:     ~/projects/my-poc/
Issue goes to: https://github.com/caburgoin/provekit/issues
```

---

## Execution Steps

### Step 1: Parse Arguments

**1.1 Extract Description**

The description is required. If empty, prompt the user:
```
What issue would you like to report?

Examples:
- "Pipeline staleness detector missed a layer"
- "Phase advance doesn't validate evidence"
- "Add support for custom maturity levels"
```

**1.2 Parse Flags**

Extract optional flags from `$ARGUMENTS`:
- `--type <bug|feature>`: Issue type (default: `bug`)
- `--command <name>`: Which ProveKit command is relevant
- `--severity <level>`: Priority level (default: `medium`)
- `--include-logs`: Include recent session context

---

### Step 2: Gather Context

**2.1 Detect Environment**

```bash
# Current project path
PROJECT_PATH=$(pwd)

# OS information
OS_INFO=$(uname -a)

# Claude Code version (if available)
CLAUDE_VERSION=$(claude --version 2>/dev/null || echo "unknown")
```

**2.2 Detect Plugin Version**

Search for ProveKit plugin version:

```bash
PLUGIN_VERSION="unknown"

# Check local development path
if [[ -f "plugins/provekit/plugin.json" ]]; then
  PLUGIN_VERSION=$(cat plugins/provekit/plugin.json | grep '"version"' | cut -d'"' -f4)
fi

# Check user's plugin cache
CACHE_PLUGIN=$(find ~/.claude/plugins -name "plugin.json" -path "*/provekit/*" 2>/dev/null | head -1)
if [[ -n "$CACHE_PLUGIN" ]]; then
  PLUGIN_VERSION=$(cat "$CACHE_PLUGIN" | grep '"version"' | cut -d'"' -f4)
fi
```

**2.3 Detect ProveKit Phase**

If the project has ProveKit state, detect the current phase:

```bash
CURRENT_PHASE="unknown"
if [[ -f ".provekit/phase-state.json" ]]; then
  CURRENT_PHASE=$(cat .provekit/phase-state.json | grep '"currentPhase"' | grep -o '[0-9]*')
fi
```

**2.4 Detect Failed Command (if not specified)**

If `--command` not provided, try to infer:
- Check `.provekit/phase-state.json` for recent activity
- Check recent conversation context
- If unable to detect, set to "unknown"

**2.5 Detect Project Type**

```bash
PROJECT_TYPE="unknown"
if [[ -f "package.json" ]]; then
  PROJECT_TYPE="node"
  if grep -q '"next"' package.json 2>/dev/null; then
    PROJECT_TYPE="nextjs"
  elif grep -q '"react"' package.json 2>/dev/null; then
    PROJECT_TYPE="react"
  fi
elif [[ -f "Cargo.toml" ]]; then
  PROJECT_TYPE="rust"
elif [[ -f "go.mod" ]]; then
  PROJECT_TYPE="go"
elif [[ -f "pyproject.toml" ]] || [[ -f "requirements.txt" ]]; then
  PROJECT_TYPE="python"
fi
```

### Step 5: Create GitHub Issue

**5.1 Generate Issue Title**

Create concise title from description:
- Truncate to ~50 chars
- Remove special characters
- For bugs: prefix with `[Bug Report]:`
- For features: prefix with `[Feature Request]:`

**5.2 Determine Labels**

Build labels array based on issue type:

#### Bug Labels

| Condition | Label |
|-----------|-------|
| Always | `bug-report` |
| Always | `triage-needed` |
| Always | `from-user` |
| If --severity critical | `severity-critical` |
| If --severity high | `severity-high` |
| If --severity medium | `severity-medium` |
| If --severity low | `severity-low` |
| If --command known | `command-{name}` |
| If phase detected | `phase-{N}` |

#### Feature Labels

| Condition | Label |
|-----------|-------|
| Always | `feature-request` |
| Always | `triage-needed` |
| Always | `from-user` |
| If --severity critical | `priority-critical` |
| If --severity high | `priority-high` |
| If --severity medium | `priority-medium` |
| If --severity low | `priority-low` |
| If --command known | `command-{name}` |
| If phase detected | `phase-{N}` |

**5.3 Execute Issue Creation**

For bugs:
```bash
gh issue create \
  --repo caburgoin/provekit \
  --title "[Bug Report]: {TITLE_SUMMARY}" \
  --body-file /tmp/provekit-issue-report.md \
  --label "bug-report" \
  --label "triage-needed" \
  --label "from-user" \
  --label "severity-{level}"
```

For features:
```bash
gh issue create \
  --repo caburgoin/provekit \
  --title "[Feature Request]: {TITLE_SUMMARY}" \
  --body-file /tmp/provekit-issue-report.md \
  --label "feature-request" \
  --label "triage-needed" \
  --label "from-user" \
  --label "priority-{level}"
```

**5.4 Add Additional Labels**

If command or phase is known, add labels:
```bash
# Add command-specific label
gh issue edit {ISSUE_NUMBER} \
  --repo caburgoin/provekit \
  --add-label "command-{command_name}"

# Add phase label
gh issue edit {ISSUE_NUMBER} \
  --repo caburgoin/provekit \
  --add-label "phase-{N}"
```

## Error Handling

### GitHub CLI Not Available

```
Error: GitHub CLI (gh) is not installed or not authenticated.

To install:
  brew install gh

To authenticate:
  gh auth login

Then retry: /provekit.report "{description}"
```

### Not Authenticated

```
Error: Not authenticated to GitHub.

Run: gh auth login

Then retry: /provekit.report "{description}"
```

### Repository Not Accessible

```
Error: Cannot access caburgoin/provekit repository.

This may be a permissions issue. Please:
1. Ensure you have a GitHub account
2. Run: gh auth login
3. Retry: /provekit.report "{description}"
```

### Empty Description

```
Error: Issue description is required.

Usage: /provekit.report "Your issue description here"

Examples:
- /provekit.report "Pipeline staleness detector missed a layer"
- /provekit.report "Add custom maturity levels" --type feature
```

## Integration Points

- **`/provekit.phase`**: Phase context is detected and included in reports
- **`/provekit.capability`**: Capability-related bugs can reference specific capabilities
- **`/provekit.pipeline`**: Pipeline staleness issues can be reported with layer context

## Important Notes

- Issues are always created in `caburgoin/provekit`, not in your current project's repo.
- The `--type` flag defaults to `bug`. Use `--type feature` for enhancement requests.
- Bugs use `severity-{level}` labels; features use `priority-{level}` labels.
- The `--severity` flag applies to both types — it maps to severity for bugs and priority for features.
- Phase detection is automatic when `.provekit/phase-state.json` exists.
- Include `--include-logs` for complex bugs to capture recent session context.
- Check existing issues at https://github.com/caburgoin/provekit/issues before reporting duplicates.
